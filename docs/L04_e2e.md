# L-04 — Pipeline end-to-end L0 su dati veri

Un solo comando fa passare dati veri per tutta la catena: dati curati (D-02) → feature (D-03) → split congelati (D-04) →
embedding esatto L0 (Q) → store (I-04) → kernel e modelli (M-02, M-03, M-04) → metriche.

```bash
make e2e-l0                                   # una config P1 (k = 5) e una P2 (Fast_Scattering), ~20 s
python experiments/e2e_l0.py --quick          # sottoinsiemi piccoli, è quello che esegue il test
python experiments/e2e_l0.py --sweep          # anteprima di E-02: k = 5, 10, 20, 50 × 5 seed, riprendibile
python -m pytest tests/test_e2e_l0.py         # si salta da solo se data/raw non c'è
```

Configurazione: 8 qubit, 2 layer, s = 0,1778 (quella congelata per l'hardware), budget di 16 configurazioni per ogni
modello, scaler stimato solo sul training. I vettori di Bloch passano davvero dallo store (`store/runs/e2e-*`, non
committati) e vengono riletti prima di allenare i modelli. Output: `results/e2e/e2e_l0.csv`, `results/e2e/e2e_l0.json`,
`results/e2e/fewshot_sweep.csv`.

## Risultati

**Few-shot (P1), anteprima di E-02.** Macro-F1 media su 5 seed, 700 glitch di test (100 per famiglia nota):

| k (esempi per classe) | SVM kernel proiettato | SVM RBF classica | differenza media (min, max) |
|---|---|---|---|
| 5 | 0,719 | 0,725 | −0,006 (−0,090, +0,072) |
| 10 | 0,777 | 0,780 | −0,004 (−0,017, +0,004) |
| 20 | 0,814 | 0,795 | +0,019 (−0,022, +0,078) |
| 50 | 0,838 | 0,838 | 0,000 (−0,017, +0,012) |

Il kernel proiettato è alla pari con l'RBF classico: è quanto chiede H1 ("non peggiore"), ma con 5 seed e un solo
avversario è un'anteprima, non il test pre-registrato (20 seed, Wilcoxon appaiato, tutte le baseline: E-02).

**Novelty (P2).** In `main` i detector usano ancora la selezione degli iperparametri di M-03/M-04, basata sul solo tasso
di falsi allarmi: qui dà AUROC 0,53 (proiettato) e 0,28 (RBF) su Fast_Scattering. È lo stesso difetto corretto nel branch
E-03 (selezione leave-one-family-out, AUROC 0,93–0,96): finché quella correzione non arriva in `models/base.py`, questi
numeri verificano che la catena funzioni, non la qualità del detector.

## Scostamenti dal task

- Le metriche vanno in CSV/JSON in `results/e2e/`, non in MLflow: MLflow non è tra le dipendenze del progetto.
- Il test d'integrazione gira in locale; la CI esiste ma è disattivata (I-02) e non ha i dati scaricati.
