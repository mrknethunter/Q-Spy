# E-03 — Novelty replay at exact L0 (RQ4, issue #29)

Core runner: `experiments/e03_novelty.py`; process-parallel entry point:
`experiments/e03_parallel.py`; configuration:
`experiments/rq4/e03_gravityspy.yaml`. This is an experiment on the current
shared modules, not another implementation of the data, feature or model APIs.
Results and the physics discussion are in [E03_results.md](E03_results.md).

## Inputs and protocol

Use default D-02 curation (318,801 rows) and the committed D-04 P2 bundle.
`verify_dataset()` verifies the full input's binary-float fingerprint before
any experiment. `load_split()` validates the frozen assets and their hashes.
Dataset SHA-256:
`c8bb3d84efa5b583ee41d671ae195b73bb5cdf901e3af03e351e1e3eac0260f1`.

Run the Fast_Scattering fold and all seven known-family rotations, each for
seeds 0–9: 80 P2 cases. `Fast_Scattering` is ALWAYS excluded from training and
validation. A rotation also excludes the selected known family. Unknown labels
are read from each frozen manifest entry, not inferred from `is_held_out`
alone (that column marks only Fast_Scattering). Full partition ID disjointness
and class exclusion are checked before selecting any subset or fitting a model.

Two evaluation scopes avoid silently mixing different questions:

- `target_family`: the chosen held-out family is positive; remaining known
  test families are negative. Other unknown families are omitted from this
  scope only. The Fast_Scattering fold is the primary replay experiment.
- `protocol_unknown`: all unknown families listed in the P2 manifest are
  positive. In rotated folds that means Fast_Scattering plus the rotated family.
  Normal examples are identical to those in the first scope. These two scopes
  coincide in the Fast_Scattering fold.

## Explicit resource-bounded evaluation

The supplied real-data configuration caps each frozen partition at 2,048
training, 2,048 validation and 8,192 test rows per case. This is **not an
uncapped evaluation on every curated row**. Labels and detector identities
are used only for protocol membership, stratified subset selection and
evaluation; they are not input features for the detectors.

Selection stays within the frozen partitions, reserves one example from each
nonempty `(label, ifo)` stratum, allocates the remaining slots proportionally
by largest remainders, then ranks IDs by SHA-256. It neither balances classes
nor generates new splits. All four detectors receive exactly the same IDs.
The test selection namespace is fixed at 2026 and independent of training
seed; its IDs are identical across ten seeds within each family rotation.
Training and validation selection varies by seed. All selected IDs are saved.

Set caps to `0` to use complete partitions, with a NEW output directory. This
can be expensive for OC-SVM and exact embedding. Such a rerun is a separate
experiment and must not be described using the capped results provided here.

## Features and representations

Call shared `make_features(train)` on selected training rows ONLY; reuse its
fitted RobustScaler for validation and test. The shared transform uses log10,
median/IQR scaling and clipping to [-1,1]. It preserves the contractual order:
`snr, peak_frequency, central_freq, bandwidth, duration, q_value, amplitude`.
Neither source labels, detector, run, confidence nor timestamp is a model input.

Use `embed(X, EmbedConfig(8, 2, 0.1778, True), "L0")` for exact Bloch vectors.
Calls are divided into ordered batches of at most 512 rows to bound Aer PUB
expansion memory. A test verifies bit-for-bit equality to one unbatched L0 call
on nontrivial inputs; batching does not approximate the statevector or kernel.
Parameters were taken from the supplied main's existing
`configs/hardware_frozen.yaml` before this E-03 test evaluation; E-03 does not
retune them from its test scores. That upstream choice is treated as fixed,
not as independent pre-registration evidence. L0 invokes no IBM hardware.
Eight qubits ensure all seven features are used; the existing map repeats the
first feature on the eighth qubit. The experiment does not change that map.

The delivered run configuration uses four worker processes, assigning complete family
rotations to workers. Each case still uses the same seed, model budget,
partition and calibration procedure. Workers write isolated temporary
directories; the parent checks worker output hashes, exact family/seed
coverage, identical provenance and settings before combining results. Worker
BLAS/OpenMP threads are limited to one. Use
`workers: 2` or `workers: 1` for less memory use; this changes scheduling, not
case selection or statistical budgets. If any child fails, the parent marks
the run `failed` and retains the staged child outputs for diagnosis. Partial
staging is never aggregated or resumed in place; restart with a new empty
artifact directory so outputs from separate attempts cannot be mixed.

- `projected_ocsvm` / `R3`: shared `RBFOCSVMBaseline` on
  `B.reshape(N,-1) / sqrt(n_qubits)`.
- `rbf_ocsvm` / `R1`: the same baseline on `X_tilde`.
- `isolation_forest`, `lof` / `X_tilde`: shared M-04 baselines. This explicit
  representation name avoids calling a nonlinear detector a linear R0 model.

For numeric gamma, RBF on the normalized Bloch vector is exactly the shared
projected kernel `exp(-gamma/n * ||B_i-B_j||²)`. This equivalence is tested.
For `scale` and `auto`, sklearn resolves gamma on that model's representation;
the resolved gamma is saved. Gamma grid indices are not matched physical
bandwidths across spaces. The encoding bandwidth `s` is applied only by `embed`.

## Equal-budget tuning and independent calibration

Every detector uses shared M-04 `fit()` with budget 8 and 3 inner CV folds,
known-only training and the same seed. This evaluates exactly eight candidates
per model (24 inner fits plus final fit); an assertion checks the budget report.
Classical grids and the known-only M-04 calibration objective remain unchanged.
Projected and ordinary OC-SVM share the same nu/gamma candidate grid and seeded
candidate indices. The grids for the other models have their own domains.
Equal configuration counts do not mean equal CPU time or equal model capacity.

### H3 hyperparameter selection status

The H3 procedure in `docs/decisions.md` is **not implemented by this E-03
runner**. The live shared method is
`models.base.BaseNoveltyModel._score_known_validation_fold` (inherited by the
M-04 novelty baselines); `models/baselines.py` contains the estimator grids,
not this shared scorer. It currently scores shuffled known-only KFold splits
by proximity of validation false-alarm rate to the candidate `nu` (or
`contamination`). It does not use the specified nine values
`c / median(d²_train)`, nested leave-one-known-class-out surrogate anomalies,
or a 5% known-validation target to select `nu`. The existing novelty `fit`
contract also receives `y=None`, so it has no known-class membership for LOCO.

The project owner clarified that `nu` must be selected from its existing
candidate grid by minimizing the absolute difference between empirical
false-alarm rate on known-class validation data and the fixed 0.05 target;
this is separate from gamma selection. The selected `nu` and achieved
validation FPR must be recorded, with deterministic tie-breaking. The owner
also authorized an explicit internal selection context in the shared base
class, preserving `fit(X, y=None)` and its existing behavior when the context
is absent; no public contract change is authorized.

The H3 implementation remains blocked by the configuration count. With the
required separate stages, the grids currently identify 9 gamma candidates and
5 `nu` candidates (14 candidate evaluations if counted additively). A
Cartesian product would instead yield 45 `(gamma, nu)` pairs, but would couple
the separate gamma and `nu` procedures. Neither interpretation yields the
required 60; the owner ruled out adding unprescribed candidates and counting
nested LOCO folds as independent configurations. This E-03 YAML still says 8,
and L-05 remains marked draft for lead approval. The exact selection objective
for ranking gamma across surrogate held-out classes also needs to be made
explicit before implementation. No H3 methodology or results have been
changed or claimed. The E-03 operating threshold described below (1%
validation FPR) is a separate post-fit threshold.


E-03 uses the shared M-04 novelty-model interface, which operates on
representations rather than precomputed kernel matrices. The projected
One-Class SVM receives the flattened Bloch-vector representation
`B.reshape(N, -1) / sqrt(n_qubits)`, while the classical RBF One-Class SVM
receives `X_tilde`. For numeric gamma, the RBF distance on the normalized
Bloch representation is mathematically equivalent to the projected kernel
defined by M-01. This equivalence does not mean that E-03 invokes the
precomputed-kernel interface directly.

The distinction between M-01 kernel construction and M-04 model execution
must be preserved. No change to their shared interfaces is made by E-03.

The availability and requirements of additional M-03 novelty detectors
(KDE, kernel-space kNN and Kernel PCA reconstruction) have not been
established by the contract alone and must be checked against the complete
M-03 task specification before deciding whether they belong in E-03.

The shared M-06 statistics module is absent in this checkout; the seed and
event bootstrap summaries described below remain E-03-local.


M-04's shared API has no fold-local preprocessing hook. The E-03 adapter wraps
its candidate estimators and preserves M-04 candidate generation, KFold
membership and known-only calibration scoring. It fits `make_features()` only
on each inner training fold, then transforms that fold's validation rows with
the same scaler. The final estimator fits a fresh scaler on the complete
selected outer training partition; only that scaler is used on outer
validation/test data. For the projected model, each fold's exact L0 embedding
follows its fold-specific scaler. The audit records each scaler's unordered
membership hash, order-sensitive row-ID hash, raw-feature hash and fitted
state; conflicting matrix/ID order registrations are rejected. No anomalous validation examples, test
scores or held-out labels select hyperparameters. LOF's shared wrapper uses
`novelty=True` and is scored only on unseen validation/test examples.

This fold-specific E-03 preprocessing differs from the hardware-point
preprocessing: `configs/hardware_frozen.yaml` specifies the scaler fitted on
P2 seed-0 training IDs, applied by `scripts/qpu_campaign.py::gravityspy_features`.
Keep E-03's fold-local behavior for its novelty replay. When making a direct
simulation-versus-hardware comparison on the hardware points, use the same
P2 seed-0 scaler and preprocessing used for those hardware points; the
fold-specific E-03 values are not produced with that same scaler.

After tuning, obtain anomaly scores with `score_samples`: HIGHER means MORE
ANOMALOUS (M-04 negates sklearn's inlier-oriented decision function).
Fit the operating threshold to the 99th percentile of independent known-only
validation scores with `method="higher"`. Flag strictly `score > threshold`;
this bounds empirical validation FPR by 1%, including ties. A constant score
distribution is recorded as collapsed, not silently repaired using test labels.

## Metrics, intervals and what they do not show

Novel = 1. AUROC is `roc_auc_score`, AP is `average_precision_score` (not
trapezoidal PR-AUC). `tpr_at_1pct_fpr` is the greatest TPR at an actually attained
test ROC point with FPR <= 0.01, using `drop_intermediate=False` and NO linear
interpolation. It is a descriptive test ROC statistic, not a deployment threshold.
The separate `tpr_validation_threshold` and `fpr_validation_threshold` use the
threshold calibrated without test data; realized test FPR need not equal 1%.
These five metrics are saved for both evaluation scopes, with test size and
positive prevalence (AP depends on prevalence).

For each held-out family, scope and metric, report the mean over ten seeds and
a 95% percentile bootstrap CI (5,000 resamples; RNG seed 29). Resampling is by
SEED, paired across the four models. Paired projected-minus-baseline differences
use the same seed draws. One-seed smoke runs explicitly have no CI.

Separately, each seed/fold/scope gets a 95% percentile interval from 1,000
stratified bootstrap resamples of selected test triggers. Each resample uses the
same known and novel trigger indices for all four models and every paired
projected-minus-classical difference. Stratification holds the test class
counts and prevalence fixed, estimating trigger-sample uncertainty conditional
on those counts and the fitted model. The event intervals are not combined with
the across-seed intervals. The resampling unit is a trigger row; D-04 has no
cross-detector coincident-event groups.

Seed intervals describe training/tuning variability **conditional on the fixed
dataset, selected test IDs and family**. They do not quantify future-run domain
shift or uncertainty over all possible unknown morphologies. Event intervals
condition on selected test class counts and the available trigger-level unit;
neither source covers dataset, label or protocol uncertainty. Rotated folds
overlap and are not independent datasets: do not
pool their event rows to obtain narrower CIs or claim a population-level quantum
advantage from these intervals. No multiplicity-corrected superiority test is
provided. The ROC plots interpolate for DISPLAY only; their bands are empirical
2.5–97.5 percentiles across seed curves, not independent event confidence bands.

## Reproduce

From the repository root, using the project's configured Python 3.12 runtime
and its already available pinned dependencies. Use a curated D-02 CSV that has
already been provisioned through the approved data workflow; this experiment
does not download or modify shared data assets:

```powershell
$env:OMP_NUM_THREADS="1"
$env:OPENBLAS_NUM_THREADS="1"
.venv\Scripts\python.exe experiments/run.py experiments/rq4/e03_gravityspy.yaml --out results/e03
```

On Linux/macOS, substitute `.venv/bin/python` and set the two thread variables
using the shell's environment syntax. Use the already configured Python 3.12
environment and pinned dependencies. Set `data_params.curated_csv` in a local
copy of the YAML to select the approved curated CSV. The loader uses
`float_precision="round_trip"`; a changed float/ID/label fails D-04
verification.
The run refuses a nonempty artifact directory; use a fresh path for reruns and
keep `params.artifact_dir` and I-03 `--out` consistent. Capped defaults are the
delivered experiment; parameter changes require their own provenance.

## Validation

`python -m pytest tests/test_e03.py tests/test_e03_metrics.py
tests/test_e03_preprocessing.py` covers full-partition exclusion before
sampling, subset membership/order invariance, score direction, ties and low-FPR
resolution, conservative validation calibration, projected-kernel
normalization, seed/event-paired inference and fold-local scaler membership.
The integration test runs all four detectors and L0 on a frozen synthetic D-04
bundle, checks equal budgets and fixed test IDs, and generates the synthetic
artifact set.

The full project test result and independent real-result checks are recorded in
the final [E03 results report](E03_results.md). Synthetic integration figures
are test outputs only and are not presented as real-data evidence.

Recheck the saved numerical artifacts and regenerate the report without fitting:

```powershell
python -m experiments.e03_report results/e03 --output docs/E03_results.md
```

This checks source/output hashes, full-partition class exclusion, selected
IDs/labels, fold-local and outer scaler membership, budgets and every saved
metric against float64 predictions, then recomputes seed and event paired
intervals. It requires the committed split bundle but not the curated CSV. With
`--curated-csv PATH`, it also rechecks the dataset fingerprint and independently
refits the outer and every inner scaler from their recorded training IDs.
